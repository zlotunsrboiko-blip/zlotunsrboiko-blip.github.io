# Пул цифровых товаров и автоматическая выдача

Версия 3 сохраняет публикацию GitHub Pages одним файлом `index.html`. Сервер работает в существующем Cloudflare Worker. Источник данных — Cloudflare D1; Google Таблицы отображают его копию.

## Что готово

- Категории с артикулом Маркета, инструкцией и сроком активации.
- Добавление аккаунтов/CDK по одному и вставкой до 100 строк из Excel.
- Просмотр, исправление и блокировка доступных товаров; даты создания и изменения.
- Резервирование всех единиц заказа одной транзакцией и защита от двойной отправки.
- Сохранение логина/CDK, пароля, 2FA и даты заказа. Шифрование секретов в D1 (AES-GCM).
- Фоновое получение заказов и автовыдача типов EMAIL и ACTIVATION_CODE при закрытом браузере.
- Учёт цены заказа и фактической выплаты после комиссий как разных величин.
- Зеркало в Google Таблицах: `Заказы — авто` и `Пул — авто`. Исторические листы не изменяются.

## Подключение Cloudflare

1. Создайте D1 database с именем `market-sales`. Подставьте её ID в `wrangler.jsonc` (binding `DB`).
2. Примените миграцию: `npx wrangler d1 migrations apply market-sales --remote`.
3. В Settings → Variables and Secrets вашего Worker задайте **Secrets**:
   - `APP_PASSWORD`: действующий пароль сервиса (минимум 16 символов).
   - `YANDEX_API_KEY`: ключ Маркета с правом обработки заказов.
   - `DATA_ENCRYPTION_KEY`: 32 случайных байта, закодированных в Base64. Сохраните резервную копию. Не меняйте ключ после загрузки пула без миграции шифрования — старые записи станут нечитаемыми.
   - `GOOGLE_SERVICE_ACCOUNT_JSON`: JSON-ключ отдельного Google service account.
4. Основной вариант синхронизации: разверните `google-apps-script/Code.gs` как Web App от владельца таблицы, заменив служебный маркер на случайный секрет. В Cloudflare сохраните URL как `GOOGLE_APPS_SCRIPT_URL`, а тот же секрет как `SHEETS_SYNC_SECRET`. Сценарий имеет доступ только через ваш Google-аккаунт; автоматические листы принадлежат приложению и перезаписываются.
5. Запасной вариант — Google service account: включите Google Sheets API, дайте service account право редактора только в таблице и сохраните JSON в `GOOGLE_SERVICE_ACCOUNT_JSON`. Переменная `GOOGLE_SHEET_ID` уже содержит ID таблицы.
6. Выполните `npm run build`, `npm test`, затем `npx wrangler deploy`. Обновите корневой `index.html` в GitHub Pages из той же версии.
7. Проверьте сайт, добавьте категории с точными `offerId` и несколько реальных свободных товаров. Затем задайте `AUTO_DELIVERY=true` в конфигурации и опубликуйте её. До этого фоновые проверки только обновляют учёт.

Cron запускается каждую минуту. Настройки в файле конфигурации — источник истины при следующей публикации; изменения через Dashboard нужно перенести в файл. При отключённом AUTO_DELIVERY ручная отправка и учёт работают.

## Порядок работы

В «Пул товаров» создайте категорию для каждого артикула. Вставьте аккаунты из Excel как `логин TAB пароль TAB 2FA`, а CDK — по одному коду на строку. Каждый товар выдаётся один раз. 2FA хранится и передаётся буквально: генератора TOTP в этой версии нет.

Автоматизация выбирает первые добавленные доступные товары. Все единицы заказа должны быть в наличии. Недостаток, отсутствующая категория и ошибка выдачи появляются в журнале; частичная выдача не выполняется. Тестовые заказы не расходуют реальный пул. Для CHAT и STEAM_GIFT автоматическая отправка не включена.

При сетевой неопределённости товар остаётся зарезервированным. При последующем статусе DELIVERED система отмечает его выданным. Без подтверждения доставки повторная отправка блокируется. Отменённый заказ не возвращает уже отправленные секреты в свободный пул. Резерв, который точно не отправлялся, можно освободить из карточки учёта. Затем исправить товар и подготовить выдачу заново.

Сумма «Выплата после комиссий» заполняется в карточке заказа из финансового отчёта. **Автоматическая загрузка и сверка финансовых отчётов в этой версии не реализована.** До сверки сумма пустая. При нескольких товарах сумма заказа в Google Таблицах показана только на первой строке, чтобы итоги не задваивались.

## Исторические данные и ограничения

Исходный Excel сохраняется отдельным архивным листом. Его записи не добавляются в свободный пул автоматически: это прошлые заказы, а не подтверждённый остаток. Даты и суммы, которых нет в источнике, не выдумываются. Фоновая сверка получает последние 30 дней и отдельно проверяет незавершённые отправки. Для старых заказов используйте «История» с нужным периодом или номером.

Для многопозиционных заказов и больших пулов рекомендуется Workers Paid из-за лимита D1-запросов на вызов Worker; при исчерпании лимита операция завершится ошибкой и будет видна в журнале. Сервис не меняет остатки карточек товаров в Маркете автоматически. Зеркало Sheets рассчитано на небольшой магазин; лимит выгрузки — 50 000 строк на лист, без автоматического удаления старых заказов.

## Локальная проверка

Node.js 22 или новее с `node:sqlite`. `npm run demo` открывает сервис на http://localhost:3210 с вымышленными товарами и временной БД в памяти. Перезапуск сбрасывает демо. `npm test` проверяет существующий API, шифрование, уникальность, резервирование, конфликты, сетевую неопределённость, автоматизацию и отсутствие двойного учёта сумм.
