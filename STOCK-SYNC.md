# Форматы, приоритет и остатки

Откройте «Пул товаров» → «Настроить» у существующей категории. Один артикул остаётся одной категорией.

## Свой пул и закупка

«Формат своего пула» сохраняет прежний тип и историю товаров. «Формат товара из магазина» независим: например, свой пул — аккаунты, MKE SHOP — CDK. Инструкция для закупки отдельная; пустое поле использует инструкцию пула. Дата активации общая.

Приоритет «Свой пул → магазин» расходует подходящий доступный запас прежде закупки. «Магазин → свой пул» сначала проверяет магазин и баланс; если до покупки их нельзя подтвердить или их недостаточно, использует свой запас. После начала закупки переход на другой источник запрещён. Полученные данные и инструкция сохраняются для повторной проверки без второй покупки. Подготовленные выдачи не пересобираются из-за изменения приоритета.

Если запаса не хватает на всё количество одной позиции заказа, у поставщика покупается вся позиция. Частичное смешивание своего пула и закупки в одной позиции не выполняется.

## Синхронизация остатка

Включается отдельно в настройках каждой уникальной категории. По умолчанию выключена. Выберите доступный склад Маркета. Универсальные товары не синхронизируются как конечный запас.

По умолчанию: проверка каждые 10 минут, публикация 35% доступного запаса с округлением вверх, порог изменения 30%, подтверждённый ноль непрерывно 5 часов перед обнулением.

Количество источника — доступный свой пул плюс остаток выбранного и включённого магазина. Резерв, выданные и заблокированные товары своего пула не учитываются. Баланс кошелька не входит в расчёт: средства для закупки нужно поддерживать отдельно. Магазины не суммируются между собой: учитывается только поставщик категории.

| Запас источника | При исходной отправке 30 → 11 |
| --- | --- |
| 23 | Оставить 11 |
| 38 | Оставить 11 |
| 20 | Отправить 7 |
| 16 | Отправить 6 |
| 39 | Отправить 14 |

База сравнения сохраняется после успешной отправки, а не сдвигается при каждом колебании. Если положительный реальный запас стал меньше опубликованного количества, количество уменьшается сразу на ближайшей проверке. Если Маркет израсходовал 30% последнего опубликованного количества или остаток стал нулём при наличии источника, запас пополняется на ближайшей проверке. После возвращения товара ожидания 5 часов нет.

Пока идёт задержка обнуления, покупатели могут оформить заказ на закончившийся товар. Задержку можно уменьшить, включая 0 часов. Ошибка API, отсутствующий товар в ответе, неполный ответ и неизвестное количество не считаются нулём: количество в Маркете не меняется, отсчёт отсутствия сбрасывается. Длительный пропуск проверок тоже сбрасывает отсчёт. Выключение синхронизации останавливает дальнейшие обновления и не обнуляет Маркет.

Кнопка проверки выполняет только чтение и показывает расчёт для сохранённой категории. Последняя проверка, переданное количество и ошибка видны в её настройках. Поставщики проверяются только по расписанию; каталог MKE общий для одного прохода, ROBOTICVN запрашивается по выбранному товару. Для ограничения нагрузки обрабатываются до трёх наступивших проверок за минуту; при большом числе категорий возможна очередь. Настройка интервала не допускает значения меньше 10 минут.

Для передачи остатков ключу Маркета нужно право «Управление товарами и карточками» либо полный доступ. Склады выбираются через документированный API: v3 для кабинетов без групп, v2 для кабинетов с группами. Остаток передаётся только для выбранного склада/магазина. На сроки появления карточки в поиске приложение влиять не может.
