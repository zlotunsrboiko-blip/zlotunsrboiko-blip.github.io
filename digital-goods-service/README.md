# Цифровые заказы — Яндекс Маркет

Обновлённая версия исходного сервиса: отправка цифровых товаров, история заказов и переписка с покупателями. JavaScript, без библиотек для работы приложения. Запускается на Node.js 22+ или Cloudflare Workers. Собственная база данных не нужна.

## Что есть в интерфейсе

- **К отправке** — цифровые заказы в обработке, ввод ключей или многострочных данных, инструкция, срок активации, просмотр доступных данных покупателя. Для нескольких единиц товара — один ключ на строку. Перед отправкой сервер повторно читает заказ и проверяет статус, состав и количество ключей.
- **История** — реальные цифровые заказы из Маркета, поиск по номеру, датам и статусу. Даты включают оба выбранных дня, максимум 30 дней за один поиск. Поиск по номеру не ограничивается выбранным периодом и статусом. Старые заказы можно искать за предыдущие периоды. Есть загрузка следующих страниц.
- **Переписка** — чаты всех магазинов выбранного кабинета, фильтры по номеру заказа и ожиданию ответа, сообщения и вложения, текстовый ответ до 4096 символов. Из заказа можно перейти в связанные чаты. Завершённые чаты доступны для просмотра. Вложения можно открыть, загрузка файлов и создание новых чатов в эту версию не входят.
- Удобная вертикальная раскладка на телефоне. Переключение вкладок сохраняет введённый текст в открытой странице; обновление списка заказов предупреждает о несохранённых данных.

## Вход и права

API-ключ вводится при каждом открытии или обновлении страницы. Он и пароль сервиса находятся только в памяти страницы, передаются серверу в заголовках HTTPS-запросов и не записываются в файлы, cookies или localStorage. При закрытии страницы они теряются. Реальный ключ из старого `.env` в поставку не включён.

В кабинете продавца у токена нужны права:

1. **Обработка заказов и учёт товаров** — чтение заказов и отправка ключей.
2. **Общение с покупателями** — чтение переписки и ответы.

Идентификаторы кабинета и магазина сохранены из исходного проекта. Для другого магазина измените переменные окружения или `vars` в `wrangler.jsonc`. Если серверные ID не заданы, их можно ввести при входе. Права и ограничения дополнительно проверяет API Маркета.

## Запуск на компьютере

Нужен Node.js 22 или новее. Запустите `START-SERVICE.cmd` либо:

```sh
npm start
```

Откройте http://localhost:3210. Установка зависимостей для локальной работы не нужна. Если нужны другие настройки, скопируйте `.env.example` в `.env`. API-ключ в `.env` не используется: вставляйте его в форму входа.

## Посмотреть без реальных заказов

```sh
npm run demo
```

В этом режиме используется только локальная имитация API. Наверху есть фиолетовая полоса «Демонстрация», тестовый ключ подставляется автоматически. Отправки и ответы меняют только вымышленные данные в памяти процесса. После перезапуска демонстрация сбрасывается. Она слушает только `127.0.0.1` и не разрешена в production.

## Размещение в интернете без постоянно работающего ПК

В проект включён отдельный адаптер **Cloudflare Workers**. Он обслуживает тот же интерфейс и те же методы, что локальный Node.js-сервер. База, диски и платные дополнения для этой версии не требуются. Бесплатность зависит от действующих лимитов Cloudflare. Сам GitHub хранит исходники, но не запускает `server.js`.

1. Создайте приватный репозиторий GitHub и загрузите **содержимое этой папки**, включая `src`, `public` и `wrangler.jsonc`. Не загружайте старый `.env`.
2. В своём аккаунте Cloudflare откройте Workers & Pages → Create application → Import a repository и выберите репозиторий.
3. Имя Worker должно совпадать с `name` в `wrangler.jsonc`: `digital-goods-service`. Если имя занято, поменяйте его в обоих местах. Корневая папка — папка с `package.json`.
4. Сборка не требуется. Команда публикации: `npx wrangler@4 deploy`.
5. В настройках опубликованного Worker → Variables and Secrets добавьте секрет `APP_PASSWORD` — случайный пароль длиной минимум 16 символов. Ключ Маркета туда добавлять не нужно. До настройки пароля операции API будут закрыты.
6. Откройте предоставленный Cloudflare адрес `https://…workers.dev` на телефоне. Введите пароль сервиса и ключ Маркета. Домашний компьютер можно выключить.

Эта поставка **не опубликована**. Аккаунт, подключение репозитория и секрет на хостинге ещё нужно настроить. Адаптер проверен локальными тестами; реальное развёртывание и доступность с вашей мобильной сети нужно проверить после публикации.

Альтернатива для обычного Node.js-хостинга: команда `npm start`, переменные `NODE_ENV=production`, `HOST=0.0.0.0`, `APP_PASSWORD` (от 16 символов), `PUBLIC_ORIGIN=https://ваш-адрес` и `PORT`, который задаёт хостинг. HTTPS обеспечивает хостинг. Публичный режим без достаточно длинного пароля не выполняет операции API.

## Что означает история

- Заказы, статусы и сообщения хранятся у Яндекса. После перезапуска приложения они снова загружаются из Маркета.
- «Маркет принял ключи» не означает, что покупатель уже получил их. Проверяйте финальный статус **Доставлен** в истории.
- История заказов не возвращает исходные ключи и инструкции. Собственный архив этих данных не ведётся.
- Имя и подменный телефон доступны через отдельный метод покупателя только для разрешённых Маркетом статусов. Для завершённых заказов этот метод не используется. В чатах отображается имя, которое Маркет включил в контекст чата.
- **Отменён** не означает «возврат оформлен». Возвраты, возврат денег и смена статусов вручную здесь не реализованы. Для разбора ситуации доступны состав заказа, статус и связанные чаты.
- Для `CHAT` и `STEAM_GIFT` интерфейс не отправляет ключи неподходящим методом; такие доставки завершаются в кабинете Маркета. `EMAIL` и `ACTIVATION_CODE` используют исходный метод `deliverDigitalGoods`.
- Нет автоматических повторов отправки. При обрыве связи результат может быть неизвестен: проверьте заказ или чат в Маркете. Блокировка повторного нажатия действует в текущей странице, а не между всеми устройствами. Не отправляйте один заказ одновременно с нескольких устройств.
- Длинная переписка загружается страницами по 100 сообщений: кнопка «Загрузить ещё сообщения». После успешного ответа обновляется история чата; в длинном чате для поиска последнего сообщения могут понадобиться следующие страницы.

## Проверки и устройство

```sh
npm test
npm run check
```

`src/api.js` — общая логика запросов к Маркету и валидация; `server.js` — локальный/Node.js-сервер; `src/worker.js` — Cloudflare; `public/` — интерфейс; `test/` — тесты и вымышленные данные. Проверки не используют реальный API-ключ и не отправляют ничего покупателям. Сетевые и чужие тексты выводятся как текст, а не исполняемый HTML. В логах приложения нет тел отправки и заголовков с ключами.
